# JSON Namespace Improvements — Design Spec

Brainstormed 2026-06-19.

---

## Goal

Extend the `json` namespace with three additions: multi-format support (JSON5 and JSONC with comment preservation), a `writePath` method for targeted single-node mutations, and a `format` opt to override extension-based auto-detection.

---

## Format Support

### Auto-detection

Format is determined by file extension unless overridden by `opts.format`:

| Extension | Parser | Serializer | Comments |
|-----------|--------|------------|----------|
| `.json` | `JSON.parse` | `JSON.stringify` | no |
| `.jsonc` | `comment-json` | `comment-json` | yes — preserved |
| `.json5` | `json5` | `json5` | no — lost on write (best-effort) |
| unknown | `JSON.parse` | `JSON.stringify` | no |

### `format` override

All read/write methods accept `{ format: 'json' | 'jsonc' | 'json5' }` to override the extension. Example: writing JSONC into a `.json` file:

```js
await json.write('tsconfig.json', data, { format: 'jsonc' })
```

Applies to: `read`, `readPath`, `readPathAll`, `write`, `modify`, `writePath`.

---

## JSONC Comment Convention

Matches the yaml namespace convention exactly — comments are encoded as `#`-prefixed string keys in the plain JS object. They survive ivm copy, `structuredClone`, and spread.

| Key | Meaning |
|-----|---------|
| `#head` | Comment before the opening brace (top of file) |
| `#tail` | Comment after the closing brace (end of file) |
| `#comment:key` | Comment on the line before `key` |
| `#inline:key` | Inline comment after the value of `key` |

### Round-trip (read → modify → write)

`json.read` on a `.jsonc` file returns a plain object with `#`-prefixed keys encoding all comments. Passing that object to `json.write` re-encodes comments back into the JSONC output. Comments survive unmodified through a `modify` cycle.

### Authoring from scratch

```js
await json.write('config.jsonc', {
  '#head': 'generated by rune — do not edit',
  '#comment:name': 'project name',
  name: 'my-project',
  '#inline:version': 'semver',
  version: '1.0.0',
})
```

Output:
```jsonc
// generated by rune — do not edit
{
  // project name
  "name": "my-project",
  "version": "1.0.0" // semver
}
```

### JSON5 write limitation

`.json5` files are parsed with the `json5` package, which has no AST — comments are not preserved on write. This is documented and expected. Users who need comment preservation should use `.jsonc`.

## `writePath`

**Signature:** `json.writePath(path, jsonPath, value, opts?)`

**Semantics:**
- Reads the file, sets (or deletes) the node at `jsonPath`, writes back
- `value === undefined` → deletes the node
- Missing intermediate nodes are created automatically as empty objects
- Requires `fs.read:<path>` and `fs.write:<path>` permissions
- Respects `format` opt and extension auto-detection (JSONC files preserve comments through the operation)
- File missing → treated as `{}`. If value provided, creates the file. If value is `undefined` (delete), no-op (no file created).

**Examples:**
```js
// set
await json.writePath('package.json', '$.scripts.build', 'tsc')

// delete (value === undefined)
await json.writePath('package.json', '$.scripts.test', undefined)

// creates intermediates
await json.writePath('config.json', '$.server.port', 3000)
// { server: { port: 3000 } }
```

**Implementation:** read → JSONPath mutation using `jsonpath-plus` callback mode (accesses `parent` + `parentProperty` to set/delete) → write back.

## Updated API Surface

```ts
// All existing methods gain opts.format
json.read(path, opts?: { throw?: boolean; format?: 'json' | 'jsonc' | 'json5' })
json.readPath(path, jsonPath, defaultValue?, { format? }?)
json.readPathAll(path, jsonPath, defaultValue?, { format? }?)
json.write(path, data, opts?: { spaces?: number; format? })
json.modify(path, callback, opts?: { initial?; spaces?: number; format? })

// New
json.writePath(path, jsonPath, value, opts?: { spaces?: number; format? })
```

---

## Dependencies

- `comment-json` — JSONC parse/stringify with comment preservation
- `json5` — JSON5 parse/stringify (best-effort, no comment preservation)

Both to be added to `package.json`.

---

## Out of Scope

- `merge` — covered by `modify` + spread
- `format` (reformat spacing) — not needed
- Symbol-based comment encoding — deferred; `#key` convention is sufficient for now and avoids ivm conversion complexity
- JSONC comment preservation for nested arrays — follows same `#comment:key` pattern; array-item comments not supported in v1 (yaml parity)
